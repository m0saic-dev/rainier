# Kits

The business side of posting: files for planning, logging and reviewing your
posts. They are not templates, and Mosaic Desktop does not load them.

## `marketing-review.xlsx`: post log and review dashboard

Download it, make your own copy, and log every post once it is live. The
Review sheet works out the rest.

| Sheet | What it is |
|---|---|
| **README** | How to log a post, the length buckets, which columns are formulas. |
| **Posts** | One row per post: date, platform, clip, section, link, length, views, likes, comments, shares, saves, trial reel, notes. Five gray formula columns (week, length bucket, engagement, engagement rate, rank) are filled down to row 1000, so a new row just works. A row counts as a post once it has a date. |
| **Review** | Views by platform, average views by length (0–15 / 15–25 / 25–40 / 40+ s), the top 10 clips with links, a 12-week trend, trial reels against main posts, and the best song sections, with four charts. Nothing to type. Dated posts with no platform, or one not on the list, show on an "Other or no platform" row, so the platform table always adds up. |
| **Calendar** | Planned posts: date, song, section, the Take Cutter file, platform(s), status (Idea, Cut, Edited, Scheduled, Posted) and the link once it is posted. |
| **Lists** | The dropdown choices and the length cut-offs. Each list has a fixed number of rows: to change a choice, rename it. |

The rows in the file are **made-up samples** so you can see it working (clip
names follow Take Cutter's `<take>_<MMmSSs>-<MMmSSs>` scheme; links point
at `@yourhandle` placeholders). Clear them when you start your own log.

It opens in Excel (Mac or Windows), Apple Numbers and Google Sheets (upload to
Drive, then Open with > Google Sheets). To keep it working everywhere, the
formulas use plain ranges and long-standing functions only (`SUMIFS`,
`COUNTIFS`, `AVERAGEIFS`, `IFERROR`, `INDEX`/`MATCH`, `LOOKUP`, `RANK`,
`WEEKNUM(date, 2)`, `HYPERLINK`): no tables, no `SORT`/`FILTER`/`XLOOKUP`.

**A quick preview shows it empty.** The file carries formulas, not their
results, so anything that shows a file without calculating it (the space bar
in Finder, a phone's Files app, Excel's Protected View for a download) shows the
gray columns, the Review sheet and its charts blank. Open it in the app (in
Excel, click Enable Editing) and they fill in.

**Your filled-in copy stays on your computer.** This repo is public: never
commit a workbook with real posts, links or numbers in it.

## Rebuilding the workbook (maintainers)

`marketing-review.xlsx` is generated by `build-marketing-review.py`. Change
the script, never the `.xlsx` by hand, then rebuild and commit both. From the
repo root:

```
python3 -m venv .venv
.venv/bin/pip install openpyxl==3.1.5
.venv/bin/python kits/build-marketing-review.py
```

The build is deterministic (fixed sample rows, fixed document dates, fixed zip
entry times), so a rebuild with the same openpyxl and zlib is byte-identical to
the committed file. A different openpyxl version still builds a correct
workbook, only with different bytes.

To check that every formula evaluates, and that the Review numbers match an
independent computation (for the sample rows in the committed file, and for two
scratch workbooks built in a temp folder: edge-case rows, and no rows at all):

```
.venv/bin/pip install formulas==1.3.4
.venv/bin/python kits/build-marketing-review.py --verify
```

`--verify` reads the `formulas` package's internal cell keys, so keep it on
1.3.4. It takes about two minutes.

`.venv/` is git-ignored.
